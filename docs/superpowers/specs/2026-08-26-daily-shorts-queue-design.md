# ショートを毎日1本、28日ぶん積む

作成: 2026-08-26

## 何を解こうとしているのか

2026-08-26 の調査で、同一 Google アカウント配下の兄弟チャンネル
「図解でわかる令和の虎」（3日違いの開設・登録者4人）が、開設から9日間 6〜16回だった
ショートを、**10日目に 5,628回へ跳ねさせ**、以降 2,000〜6,000回で回し続けていることが分かった。
ひろゆき解説chは8日で投稿が止まっている。観測されている差は継続だけ。

### 止まった理由は「やめた」ではなく「上げ切れなかった」

`recipes/shorts/` に14本のレシピがあり、`work/shorts/` に14本ぶんの `video.mp4` があるのに、
`state/published.json` に載っているのは5本だけ。残り9本は**ビルド済みのまま予約日を過ぎた。**

`videos.insert` は1本 1,600 ユニット、1日の枠は 10,000。**1日5〜6本が上限**で、
`publish_shorts.py` は「毎日回して続きから上げる」前提で書かれている。それが回されなかった。

**設計上の穴はここ。** 「作る」と「上げ切る」が別々の手作業で、後者に歯止めも通知も無い。

## 決めたこと

| 項目 | 決定 | 根拠 |
|---|---|---|
| ペース | **1日1本 × 28日**（08/27〜09/23） | 跳ねた令和の虎と同じペース。在庫28本がちょうど28日ぶん。2本/日だと14日で尽きて、跳ねる前に切れる |
| 時刻 | 07:00 JST 固定 | **根拠は無い。** 既存6本の最多再生（20回）は朝枠だが、その20回は検索流入なので時刻の証拠にならない。既定の第1スロットを踏襲しただけ |
| タイトル | **変えない**（`【ひろゆき】〇〇【切り抜き】`） | 変える変数を「毎日続ける」1つに絞る。令和の虎の型（セリフ引用＋ハッシュタグ）に寄せたくなるが、コムドット名場面chはハッシュタグ入りでも跳ねていないので、型が効くという根拠が無い |
| 既存9本 | **再ビルドせず日付だけ振り直す** | 中身は問題ない。捨てる理由が無い |
| 日次自動化 | **今回は入れない** | オーナー判断。今日6本上げて、実際に上がるのを見てから決める |

## やること

### 1. `plan_shorts.py` に「1日1本」を足す

現状 `SLOTS = {"am": 7, "pm": 18}` が固定で、必ず1日2本を吐く。
`--slots am` のように使うスロットを選べるようにする。既定は現状維持（am,pm 両方）。

### 2. 既存9本の予約を 08/27〜09/04 に振り直す

`2026-08-22-pm` 〜 `2026-08-26-pm` の9本。id が日付そのものなので、**3か所を揃えて改名する**:

- `recipes/shorts/<old>.json` → `<new>.json`（中の `id` と `publish_at` も書き換え）
- `work/shorts/<old>/` → `work/shorts/<new>/`
- `work/shorts/<new>/meta.json` の `id` と `publish_at`

**改名が要る理由**: `publish_shorts.py` のキューは `sorted(SHORTS.glob("*.json"))` ＝
**ファイル名順**であって `publish_at` 順ではない。id が日付を持つ前提が崩れると投稿順が壊れる。

### 3. 9本の窓を `used_shorts.json` に先行登録する

`mark_used()` はアップロード成功時にしか呼ばれない。9本はまだ未投稿なので、
このまま `plan_shorts.py` を回すと**同じ区間が新規19本にも選ばれる**。
先に窓を登録して二重取りを防ぐ。`mark_used` は `short_id` で重複を弾くので、
あとで実際に上がったときに壊れない。

### 4. 新規19本を計画・ビルド（09/05〜09/23）

素材は7本の親エピソード全部が `work/` にある（確認済み）。ダウンロード不要。

### 5. 今日6本だけ上げる（08/27〜09/01）

`publish_shorts.py --limit 6` = 9,600 ユニット。長尺は今日上げない前提。

## 積み残し（このセッションでは解かない）

- **22本ぶんの上げ残りをどう捌くか。** 日次実行の担保が無いままだと、前回と同じ場所で切れる。
  タスクスケジューラ登録が最有力だが、今日6本が実際に上がるのを見てから判断する
- 親の長尺 `2026-08-27-fudosan`（`TtJKOPH0PCU`）は **private のまま**。
  これを親に持つショートが概要欄で非公開動画に導線を張る。09/05 以降に当たるので、
  それまでに長尺を公開すること
- 「続ければ跳ねる」は成功例 n=1 の仮説。跳ねが自然な配信テストか外部要因かは、
  令和の虎の Analytics を見ないと分からない（現在の token は ひろゆき解説ch にバインド）
