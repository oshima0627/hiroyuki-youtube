# 毎日2本のショートを長尺の在庫から自動で作る

2026-08-19

## 何を作るか

既存の長尺レシピが持つクリップ（1問1答の区間）を横断して選び、
縦型ショートを14本組み、**朝7:00 と夜18:00 JST に1本ずつ・7日間**予約公開する。

素材は既に `work/clips` にある（59ファイル / 565MB）。再取得はしない。

## 決まっていること（2026-08-19 に本人が選択）

| 項目 | 決定 |
| --- | --- |
| 切り出し方 | クリップ横断で選抜。1つの長尺から複数本出してよい |
| 投稿時刻 | 07:00 と 18:00 JST（22:00 UTC 前日 / 09:00 UTC） |
| 初回の量 | 7日ぶん＝**14本** |
| フック | **全自動**。人の確認を挟まない |

## 実測（設計の根拠）

| 測ったもの | 値 |
| --- | --- |
| 候補クリップ | 47本（親の長尺が published.json にあり、素材がローカルにある） |
| 素材 | `work/clips` 59ファイル 565MB。ダウンロード不要 |
| フックの限界 | 76px・幅968px → **12文字**。既存の14文字は既に縮小されていた |
| クォータ | `videos.insert` 1,600 / 10,000 per day → **1日6本**。14本は3日に分ける |

## 構成

```
plan_shorts.py    47候補 → スコア順 → 窓決め → フック生成 → recipes/shorts/*.json
build_short.py    1ファイル = 1本 → work/shorts/<id>/video.mp4   （改修）
publish_shorts.py 未投稿を上限6本まで、各自の publish_at で予約投稿  （新規）
```

### plan_shorts.py

候補の除外と採点は既存資産を使う。`signals.json` の `avoid` / `lexical` / `comment_marks`。

窓の決め方が新規。クリップは平均63〜108秒で Shorts の適正（22〜73秒）より長い。
**字幕行の境界にスナップして** 45〜70秒の窓をスライドし、断言密度が最大の窓を取る。
行の途中では切らない。

フックは窓の中の最初の断言行から作る。文末（`〜と思います` 等）を落として言い切りにし、
**PIL で実測して 76px で1行に収まらなければ短縮する。目測しない。**

採否ゲート（1つでも落ちたら捨てる）:

- 窓が 22〜73秒
- フックが実測 56px 以上で1行に収まる
- `AVOID` に当たらない
- 親の長尺が `published.json` にある（概要欄の導線が張れる）
- `state/used_shorts.json` に無い

同じ長尺から連続で出さないよう、親エピソードのラウンドロビンで並べる。

### build_short.py の改修

いまは `recipe["short"]`（単数）＋ `recipe["clips"][idx]`。
**単体のショートレシピ1ファイル**を受ける形に広げる。
顔検出・正方形クロップ・フレーム合成には触らない（動いている）。
既存の埋め込み形式も読めるまま残す。

### upload_youtube.py の改修

`with_long_form_link` が `id` の `-short` サフィックスから親を逆算している。
1エピソードから複数本出すと破綻するので **meta.json の `parent` を見る**。
無ければ従来のサフィックス規則にフォールバック。

## 検証

自己申告を根拠にしない。次を画面に出す。

- 14本ぶんのフック全文と秒数（自動生成なのでここが全て）
- `ffprobe` の実測（解像度・尺・14本）
- 冒頭フレームの実PNG（顔が切れていないか、文字が縮んでいないか）
- 投稿後の `ops_youtube.py --status`

## 前提として引き受けるリスク

README の実測で、既存ショート1本は2再生。**長尺への導線として機能していない。**
毎日出すことで1本あたりの効果が上がる根拠はまだ無い。
14本を1週間回して初めて測れる、という前提でこれを組む。
