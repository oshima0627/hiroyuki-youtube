## 尺は15分未満に収める

**電話番号が未確認のチャンネルは15分を超える動画を上げられない。**
アップロードのAPI呼び出しは成功するが、**処理が中止される**。
実際に16分36秒を上げて止められた（2026-08-14）。

このときの見え方が紛らわしい。**Studio には「処理を中止しました／動画が
長すぎます」と残り、削除ボタンが出る。** 一方 Data API の videos.list には
出てこなくなり、uploads プレイリストでは "Deleted video" と表示される。
API だけ見ていると消えたように見えるが、実体は残っているので手で消す。

電話番号は1つにつき**1年で2チャンネルまで**しか使えず、この番号は
他のチャンネルで使い切っている。1年経つまでは未確認のまま運用する。

未確認で使えないもの:

| 機能 | 影響 |
| --- | --- |
| 15分を超える動画 | 構成そのものを縛る。市場相場は13〜20分でその下限で戦うことになる |
| カスタムサムネイル | 自動生成の3枚から選ぶ。CTRに効くので痛い |
| ライブ配信 | 使わない |

### サムネイルが使えないぶんは見出し帯で埋める

`thumbnails.set` は 403 を返す（2026-08-17 実測）。

```
The authenticated user doesn't have permissions to upload and set
custom video thumbnails.
```

**本編のフレームがそのままサムネイルになる。** 自動生成の候補は動画の
およそ25%・50%・75%地点から作られるので、そこに何が写っているかがCTRを決める。
実物を見ると差が出ていた。

| 動画 | 自動サムネイルの中身 | 再生 |
| --- | --- | --- |
| EP002 `ssy9pUfgCNc` | 見出し帯「05 大学入試に面接は必要か」＋本人 | 115 |
| EP003 `jaQZTRkMN4E` | 見出し帯「05 現金を持ち続けることの意味」＋本人 | 276 |
| EP004 `1Qk53tSphDg` | **帯なし。** 元配信のコメント欄が写っただけ | 46 |

見出し帯は冒頭6秒しか出していなかったので、90秒級のクリップでは帯の
乗っている時間が7%しかなく、候補に文字が入るかどうかが運だった。
**6秒を過ぎたら細い帯（`telop.render_top_bar_slim`）に差し替えて出し続ける。**
EP005 で25%・50%・75%の3点を抜き、3点とも帯と本人の顔が入ることを確認した。

再生数の差が帯のせいだとまでは言えない（テーマも違う）。言えるのは
**候補フレームに文字が入るかどうかを運任せにしなくなった**ことだけ。

### 冒頭カードのフレームは目で選ぶ

`thumbnail.py` の顔スコアによる自動選択は外すことがある。EP006 では
**後頭部のフレームを選んだ**（2026-08-20 の回では逆に妥当なものを選んだ）。
自動任せにせず、コンタクトシートを見て `thumb.at` を書くこと。

```bash
python scripts/contact_sheet.py work/<id>/video.mp4 sheet.png 40 80 110 150 200 260
#   → 良い秒を読んで recipes/<id>.json の thumb.at に書く
#   → thumbnail.py → build_episode.py --concat-only
```

**`ffmpeg -vf fps=1/N,tile=...` で作った一覧の時刻は当てにならない。**
タイルの並びと `drawtext` で焼いた時刻がずれて、実際とは違う秒を二度読んだ。
`contact_sheet.py` は `-ss <秒> -i` で1枚ずつ抜くのでずれない。

`plan_episode.py --target` は**完成尺**を指す（本編の合計ではない）。
解説板が後から乗るので、本編の合計で指定すると必ず超過する。
既定は 870秒（14:30）で、900秒に対して30秒の余裕を見ている。

`upload_youtube.py` は15分超を拒否する。確認が済んだら `--allow-long`。

## パイプライン

```
1. fetch_source.py --subs-only   字幕とメタだけ取る（候補検討はこれで足りる）
2. fetch_topics.py --save        GCD の公式トピック → topics.json
3. probe_signals.py --no-audio   コメント + 熱 → signals.json
4. plan_episode.py --theme       配信をまたいでテーマで束ねる → 構成案
   ↓ recipes/<id>.json に解説（note）とまとめ（summary）を書く
5. fetch_clips.py                使う区間だけ落とす（全編は落とさない）
6. build_episode.py              本編 → 解説板 → 本編 … を連結
7. thumbnail.py                  サムネイル
8. upload_youtube.py             private → 内容確認 → --publish
```

**`--subs-only` と区間ダウンロードで、全編（1本4〜8GB）を落とさずに済む。**
実測で13区間・17分ぶんが合計150MB程度。

## 作り直したもの

### 区間の探し方（`qa.py` ← `moments.py`）

令和の虎は「持ち込み→詰め→判定」という一本の流れなので、スコアの積分が最大に
なる連続区間をスライディングウィンドウで1つ取る設計でよかった。
**ひろゆきは質問と回答の繰り返しなので、同じことをすると質問の途中で切れる。**

先に質問境界でブロックに割り、ブロック単位でスコアを出して束ねる。
競合上位4本も全員がチャプター5〜8個の構成だった（2026-08-14 実測）。

**令和の虎ガイドラインの「分割された本編を連結した投稿の禁止」は、
ひろゆき側の許諾条件には無い。** 混同しないこと。

### 語彙（`signals.py` の `LEXICON`）

令和の虎の「詰め／金額／判定」は使えない。「質問／断言／根拠／留保」に置き換えた。

### 信号の重み

**音量の重みを 0.35 → 0.15 に下げた。** ひろゆきは怒鳴らない。
令和の虎では虎が激怒すれば必ず音量に出たが、こちらはビールを飲みながら淡々と話す。
代わりにコメント言及を 0.30 → 0.45 に上げた。

### 要注意話題の自動除外（`AVOID`）

政治・特定個人・センシティブに触れるブロックを候補から落とす。新規。
実素材57ブロック中18が該当した。

## 実測値（`23vSB2fXjc8` / 3:23:01 / 26.6万回）

| 項目 | 値 |
| --- | --- |
| 字幕 | 4,362行 |
| 語彙 | 351件（断言181 / 質問99 / 根拠53 / 留保18） |
| 要注意 | 77件 |
| コメント言及 | 243箇所（99件から） |
| ヒートマップ | 100区間（この回は存在した） |
| ブロック | 57（うち要注意18） |
| 束ねた結果 | 7本 / 17〜19分（現在は15分未満に制限） |

### パラメータはこう決めた

**`MERGE_GAP` 45秒 → 18秒。** 45秒だと連続する別の質問まで畳んでしまい、
毒親の回答と KADOKAWA の回答が1ブロックに融合した。

**束ねる順は生スコアでも密度でもなく `score / sqrt(秒)`。**

| 並べ替え | 結果 | 判定 |
| --- | --- | --- |
| 生スコア順 | 4本 / 17.8分 | チャプターが足りない |
| 密度順 | 8本 / 10.3分 | 尺が足りない |
| **sqrt順** | **7本 / 18.0分** | **これを採る** |

コメント言及は長いブロックほど多く入るので、生スコア順にすると長い数本だけで
尺が埋まる。かといって毎分あたりの密度にすると45秒級ばかりが選ばれる。

## ヒートマップは主軸にできない

`tora-kirinuki` の実測で、存在するのは30本中7本（23%）だけ。
生成条件は「5万回以上」かつ「3週間以上経過」の両方。
**新着＝一番切り抜きたい動画では使えない。**

`23vSB2fXjc8` で取れたのは 26.6万回・2ヶ月前で両条件を満たしていたから。

## 共演者の検出

**yt-dlp の `uploader` / `channel` では検出できない。**
実測（2026-08-14）で、共演回 `naVkgtFmRvg` も単独回 `23vSB2fXjc8` も
`uploader` は等しく `"ひろゆき, hiroyuki"` だった。
共演者の名前が出るのは**概要欄とチャプターの中**（「ゲスト紹介：実業家 桑田龍征」など）。

チャンネル名自体に半角カンマが入っているので、カンマ区切りを共同投稿と
誤認しないこと（最初にこれで誤検出した）。

検出は完全ではない。**最終判断は人がする。**

## 独自性は18%を確保している

YouTube の「再利用されたコンテンツ」対策。テロップだけだった頃は
独自要素が 873秒中60秒（6.9%）で、数カ所サンプリングされたら素の映像に
当たる状態だった。解説板（静止画＋VOICEVOX の読み上げ）を各クリップの
直後に挟んで 996秒中183秒（18%）にした。

**ただし独自性と再生数は連動しない。** 実測した競合はどれも解説なしで
7,000〜9,500回（20時間）出ている。独自性は審査を通すためのもので、
再生数は題材とタイトルとサムネで決まる。

## ショートを毎日2本出す

長尺の在庫（1問1答のクリップ）を横断して選び、**朝7:00 と夜18:00 JST**に
1本ずつ出す。素材は長尺のときに落とした `work/clips` をそのまま使う。

```bash
python scripts/plan_shorts.py --days 7 --from 2026-08-20 --write
for f in recipes/shorts/*.json; do python scripts/build_short.py "$f"; done
python scripts/publish_shorts.py          # 上限5本。翌日また実行すると続きから
```

**候補は親の長尺が投稿済みのものに限る。** 概要欄の「▼この回をフルで見る」に
長尺のURLを差し込めないと、ショートを見た人の行き先が本人のチャンネルに
しか無くなる。2026-08-19 時点で候補31本。

### フックは字幕から作らない

**自動字幕から言い切りを削り出す設計は成立しなかった（2026-08-19 実測）。**
単語が崩れる（「フルリモート」→「振りモ」「振リモート」）うえ、「断言」語彙に
当たる文は108字・154字でフィラーまみれだった。崩れた字幕から作った文言を
画面に大きく出すのは、本人が言っていないことを言わせることになる。

代わりに **clips[].title**（長尺を組んだときに人が書いた見出し）を使う。
新しく人手は増えない。

**フックは PIL で実測して1行に収める。** 76pxで幅968pxに入るのは12文字まで。
56pxまでの縮小を許し、それでも入らないものは**削らずに捨てる**。
一度「〜したい」を機械で落としたら「在宅テスターのバイトから抜け出」になった。

### クロップは1フレームで決めない

**当初は開始3秒地点の1枚だけ測って固定していた。** ひろゆきはよく動くので、
14本作って3本で顔が左端で切れた（コンタクトシートで確認）。
2秒に1枚ずつ窓全体を走査して決める。

縦は**分位点**で妥協する。合併（最小・最大）にすると、頭がいちばん下がった
フレームの顎とカードがいちばん高いフレームの上端が両立せず、14本中7本で
口から下が切れた。横は合併のまま（左右のはみ出しのほうが目立つ）。

**残ったカードの侵入は黒帯で潰す。** スパチャの上端は1つの窓の中で
650〜794px を行き来する（実測）。幾何だけでは毎フレーム外し切れない。

### クォータで3日に分かれる

`videos.insert` は1,600ユニット、1日10,000。**1日6本**が上限で長尺も同じ枠を
使うので、`publish_shorts.py` の既定は5本。14本＝7日ぶんは3日に分けて上げる。
上げ終わったものは `published.json` に載るので、翌日そのまま再実行すればよい。

**予約時刻を過ぎたものは上げない。** publishAt に過去を渡すと即時公開になる。

## 公開後の運用（`ops_youtube.py`）

```bash
python scripts/ops_youtube.py --status      # 実状態を取って published.json を直す
python scripts/ops_youtube.py --playlist    # 再生リストに全話を入れる
python scripts/ops_youtube.py --crosslink   # 概要欄に他の回への導線を足す
```

**`published.json` は投稿時の申告であって実状態ではない。** 予約公開が
発火しても誰も書き戻さないので `privacy_status` は private のまま古くなる。
2026-08-17 に EP003・EP004 が public になっているのに記録は private だった。
`--status` は API の実状態で上書きし、`publish_at` と再生数も残す。

再生リスト: <https://www.youtube.com/playlist?list=PLYz8LvlJhib0>

**導線を足す根拠は流入の内訳。** Analytics（2026-08-01〜14）で取れたのは
関連動画12・検索1で、**外から来た人をチャンネル内に留める経路が概要欄しかない**。
`--crosslink` は概要欄の末尾に再生リストと直近の回を差し込む。
`videos.update` は part を丸ごと置き換えるので、snippet を送るときは
title も tags も一緒に送らないと消える。
