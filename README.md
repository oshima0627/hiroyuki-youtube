## 尺は15分未満に収める

**電話番号が未確認のチャンネルは15分を超える動画を上げられない。**
アップロードのAPI呼び出しは成功するが、**処理が中止される**。
実際に16分36秒を上げて止められた（2026-08-14）。

このときの見え方が紛らわしい。**Studio には「処理を中止しました／動画が
長すぎます」と残り、削除ボタンが出る。** 一方 Data API の videos.list には
出てこなくなり、uploads プレイリストでは "Deleted video" と表示される。
API だけ見ていると消えたように見えるが、実体は残っているので手で消す。

電話番号は1つにつき**1年で2チャンネルまで**しか使えず、この番号は
他のチャンネルで使い切っている。1年経つまでは未確認のまま運用する。

未確認で使えないもの:

| 機能 | 影響 |
| --- | --- |
| 15分を超える動画 | 構成そのものを縛る。市場相場は13〜20分でその下限で戦うことになる |
| カスタムサムネイル | 自動生成の3枚から選ぶ。CTRに効くので痛い |
| ライブ配信 | 使わない |

`plan_episode.py --target` は**完成尺**を指す（本編の合計ではない）。
解説板が後から乗るので、本編の合計で指定すると必ず超過する。
既定は 870秒（14:30）で、900秒に対して30秒の余裕を見ている。

`upload_youtube.py` は15分超を拒否する。確認が済んだら `--allow-long`。

## パイプライン

```
1. fetch_source.py --subs-only   字幕とメタだけ取る（候補検討はこれで足りる）
2. fetch_topics.py --save        GCD の公式トピック → topics.json
3. probe_signals.py --no-audio   コメント + 熱 → signals.json
4. plan_episode.py --theme       配信をまたいでテーマで束ねる → 構成案
   ↓ recipes/<id>.json に解説（note）とまとめ（summary）を書く
5. fetch_clips.py                使う区間だけ落とす（全編は落とさない）
6. build_episode.py              本編 → 解説板 → 本編 … を連結
7. thumbnail.py                  サムネイル
8. upload_youtube.py             private → 内容確認 → --publish
```

**`--subs-only` と区間ダウンロードで、全編（1本4〜8GB）を落とさずに済む。**
実測で13区間・17分ぶんが合計150MB程度。

## tora-kirinuki から流用したもの

- `subtitles.py`（VTTパーサ）はそのまま
- `signals.py` の音量・ヒートマップ・コメント集計はそのまま

## 作り直したもの

### 区間の探し方（`qa.py` ← `moments.py`）

令和の虎は「持ち込み→詰め→判定」という一本の流れなので、スコアの積分が最大に
なる連続区間をスライディングウィンドウで1つ取る設計でよかった。
**ひろゆきは質問と回答の繰り返しなので、同じことをすると質問の途中で切れる。**

先に質問境界でブロックに割り、ブロック単位でスコアを出して束ねる。
競合上位4本も全員がチャプター5〜8個の構成だった（2026-08-14 実測）。

**令和の虎ガイドラインの「分割された本編を連結した投稿の禁止」は、
ひろゆき側の許諾条件には無い。** 混同しないこと。

### 語彙（`signals.py` の `LEXICON`）

令和の虎の「詰め／金額／判定」は使えない。「質問／断言／根拠／留保」に置き換えた。

### 信号の重み

**音量の重みを 0.35 → 0.15 に下げた。** ひろゆきは怒鳴らない。
令和の虎では虎が激怒すれば必ず音量に出たが、こちらはビールを飲みながら淡々と話す。
代わりにコメント言及を 0.30 → 0.45 に上げた。

### 要注意話題の自動除外（`AVOID`）

政治・特定個人・センシティブに触れるブロックを候補から落とす。新規。
実素材57ブロック中18が該当した。

## 実測値（`23vSB2fXjc8` / 3:23:01 / 26.6万回）

| 項目 | 値 |
| --- | --- |
| 字幕 | 4,362行 |
| 語彙 | 351件（断言181 / 質問99 / 根拠53 / 留保18） |
| 要注意 | 77件 |
| コメント言及 | 243箇所（99件から） |
| ヒートマップ | 100区間（この回は存在した） |
| ブロック | 57（うち要注意18） |
| 束ねた結果 | 7本 / 17〜19分（現在は15分未満に制限） |

### パラメータはこう決めた

**`MERGE_GAP` 45秒 → 18秒。** 45秒だと連続する別の質問まで畳んでしまい、
毒親の回答と KADOKAWA の回答が1ブロックに融合した。

**束ねる順は生スコアでも密度でもなく `score / sqrt(秒)`。**

| 並べ替え | 結果 | 判定 |
| --- | --- | --- |
| 生スコア順 | 4本 / 17.8分 | チャプターが足りない |
| 密度順 | 8本 / 10.3分 | 尺が足りない |
| **sqrt順** | **7本 / 18.0分** | **これを採る** |

コメント言及は長いブロックほど多く入るので、生スコア順にすると長い数本だけで
尺が埋まる。かといって毎分あたりの密度にすると45秒級ばかりが選ばれる。

## ヒートマップは主軸にできない

`tora-kirinuki` の実測で、存在するのは30本中7本（23%）だけ。
生成条件は「5万回以上」かつ「3週間以上経過」の両方。
**新着＝一番切り抜きたい動画では使えない。**

`23vSB2fXjc8` で取れたのは 26.6万回・2ヶ月前で両条件を満たしていたから。

## 共演者の検出

**yt-dlp の `uploader` / `channel` では検出できない。**
実測（2026-08-14）で、共演回 `naVkgtFmRvg` も単独回 `23vSB2fXjc8` も
`uploader` は等しく `"ひろゆき, hiroyuki"` だった。
共演者の名前が出るのは**概要欄とチャプターの中**（「ゲスト紹介：実業家 桑田龍征」など）。

チャンネル名自体に半角カンマが入っているので、カンマ区切りを共同投稿と
誤認しないこと（最初にこれで誤検出した）。

検出は完全ではない。**最終判断は人がする。**

## 使い方

```bash
python -m pip install --user -r requirements.txt

# 素材を集める
python scripts/fetch_source.py --latest 10 --list      # 配信アーカイブ一覧
python scripts/fetch_source.py --subs-only <URL>       # 字幕だけ
python scripts/fetch_topics.py --save                  # 公式トピック
python scripts/probe_signals.py <video_id> --no-audio

# 1本ぶんの構成を組む
python scripts/plan_episode.py --theme 仕事 転職 会社 --out recipes/ep.json
#   → clips に note（20文字以上の解説）と summary を書く

# 作る
python scripts/fetch_clips.py recipes/<id>.json        # 区間だけ落とす
python scripts/build_episode.py recipes/<id>.json
python scripts/thumbnail.py recipes/<id>.json

# 出す
python scripts/upload_youtube.py --auth-only           # 初回だけ
python scripts/upload_youtube.py work/<id>             # private
python scripts/upload_youtube.py work/<id> --publish
```

**VOICEVOX の起動が前提**（青山龍星 ノーマル / id 13）。
**yt-dlp は cookie が要る**（Firefox 既定。cookie 無しだと403が続く）。

## 独自性は18%を確保している

YouTube の「再利用されたコンテンツ」対策。テロップだけだった頃は
独自要素が 873秒中60秒（6.9%）で、数カ所サンプリングされたら素の映像に
当たる状態だった。解説板（静止画＋VOICEVOX の読み上げ）を各クリップの
直後に挟んで 996秒中183秒（18%）にした。

**ただし独自性と再生数は連動しない。** 実測した競合はどれも解説なしで
7,000〜9,500回（20時間）出ている。独自性は審査を通すためのもので、
再生数は題材とタイトルとサムネで決まる。
